Re: EasyABC Questions

I downloaded EasyAbc, out of curiousity. It is possible to display numbered titles & include Notes (&/or History) with postscript routines. I’d also recommend contacting Nils Liberg so he knows of your interest in these features.

In the meantime here is how postscript works for each of these routines. Insert the commands on the lines directly above the X:reference number in the abc header. Remember to use the double percentage > %%

%%withxrefs
%%writefields N 1
X:1
T:8-)
M:12/8
etc.

The first command (%%withxrefs) gives numbered titles. The 2nd command (%%writefields N 1) displays any notes which are written in the N:Notes field. You can also show H:History by using the <write fields> command. On the third line type;
%%writefields H 1.

Some of this is in the EasyAbc Help page. Below are the steps to take you to the postscript commands;

Help >
Show fields and commands reference >
ABC fields and commands reference >
Other commands >

%%writefields is a new command & it isn’t shown in the help file. But it does work. I used it in EasyAbc.

Ben’s got the right answers. Another way to do this sort of thing, particularly useful if you want to do the same thing in multiple files, is to create a format file. This is just a simple text file (though I put the “.fmt” extension on mine to keep track of them. In the text file you put the commands you want to use but WITHOUT the %% . So,

withxrefs
writefields N 1

in the above example. There are a huge number of things you can do to your abc files for print out. I’d suggest a look at the ABCPlus manual on Guido Gonzato’s page. It is a bit out of date but will cover most of what you might want to know.

Hope this helps.

1) EasyABC uses abcm2ps internally.
2) EasyABC also uses abc2midi internally and I believe, but am not sure, that the repeat issues have been solved.
3) error checking that is done by abcm2ps is reported in EasyABC, but the locations are not nearly as nicely reported. I don’t believe EasyABC does the measure duration checking Barfly did.
4) Files can be sorted quite flexibly in EasyABC (by title, tune type and essentially any other header). X: can be renumbered.

EasyABC is, fortunately or unfortunately about the only extended program for the Mac. The good thing is you can use it on your current machine and see how it works for you. DON’T point at anything except format files when you start using it. Out of date abcm2ps or abc2midi files will not work because EasyABC expects the capabilities in the newer files. Use the program just as it downloads at first. Then if everything works “OK” but there are things that don’t work for you drop me a note. You need to set up page numbering and a few other things that were point and click in Barfly by using either format files or placing command line things in the ABC settings. It is quick and easy and can be done just one time.

I sound like an apologist for EasyABC. I am not. Re: EasyABC Questions

The problem with Nigel’s file turned out to be that it was encoded using utf-8 but didn’t specify the encoding (see below for how this is done). For this reason EasyABC assumed its character encoding was latin-1 which resulted in some quotation characters showing up a bit funny which later made ghostscript crash upon conversion to PDF (at least when I tried it in Windows). By adding info about the charset (or by declaring the file as adhering to the ABC 2.1 standard which uses utf-8 by default) it should work.

See http://abcnotation.com/wiki/abc:standard:v2.1#charset_field

@Jack
I see. Do you have different macros for different voicings then? One problem with macros is that they would make it harder to keep track of character offsets (eg. if abcm2ps reports an error in column 10 on a line I would have to work it out backwards what column that is in the unprocessed code). It wouldn’t be impossible however.

EasyABC Questions … & answers ;-)

You gotta love this. The Abc 2.0 Draft standard seemed to be ready to live it’s life to a ripe old age. About a year ago the push was on to set the standard. Everything was relatively quiet until then;

The ABC Music standard 2.0 (draft IV, 14/8/2003)
3.3.4. Charset field
“Software that exports ABC tunes conforming to this standard, should include a charset field if an encoding other than iso-8859-1* is used.”

The abc music standard 2.1 (Dec 2011)
3.1.17 I: - instruction

~

Charset field
“Software that exports abc tunes conforming to this standard should include a charset field if an encoding other than utf-8 is used. All conforming abc software must be able to handle text strings coded in utf-8 and us-ascii. Support for the other charsets is optional.”

*latin-1

Some things I’ve noticed in EasyABC.

If you’re using the “R:” field for the tune type like “R:Reel”, “R:Jig” or whatever, you can sort on that field - and it will be sorted alphabetically by title as expected. However, if you append a number to the field such as “R:Jig 29” the sort will be by that field (R) but ordered according to the number you’ve assigned thus retaining your preference for the order in which all of the tunes of a type will be displayed.

You can also retain the order of your tunebook by dedicating another field such as “Z:” or “I:” (although “I” might not be such a great idea) by assigning a number to that field in accordance to the order of your tunebook. Then, if you do a sort by Title or X, you can at least revert back to what you had. It is tedious to start adding numbers to everything but it might with the worth the effort.

Get the tunes in the order you want that is unusual. Renumber the X field. Then you can sort however and always return to the order you set. Also, if you are working with the file in one session control Z will take you back through changes you’ve made. If the changes are just sorts you should be able to get back to where you began. Of course if you save then all that and restart later all will be forgotten. And, did you notice that setting the R: field will automagically adjust the playback style? You may or may not like the results, but you can adjust if you wish, and anything is better than the mechanical results one usually gets.
