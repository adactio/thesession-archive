ABC Transcription Tools - August 2024 Updates

You can now export each tune in a tunebook to its own individual PDF file.

If optional play links are specified in the ABC for the tunebook, the individual PDF files will play when the title is clicked.

This was a huge technical challenge, not only am I exporting each tune to its own PDF file, I’m also optimizing the PDF size so that you don’t have to do any post-processing of the files.

I’ve run thousands of tunes through it, including successfully exporting all 1006 tunes of the “King Street Sessions” tunebook as individual PDF files.

For the power users of the tool, I’ve added support for using regular expressions as the matching pattern in the Find and Replace feature.

This is an extremely powerful new feature that allows considerable flexibility when doing Find and Replace.

I’m not going to teach you how to use regular expressions, there are many websites and YouTube videos on the subject.

One website I really like to both test and learn about regular expressions is:

https://regex101.com/

I’m using the Javascript syntax for the regular expressions.

You don’t need to wrap them with slashes or include any flags, I take care of all that for you behind-the-scenes.

Just enter the regular expression you want to match in the Find text area and the text to replace the matches in the Replace text area.

Re: ABC Transcription Tools - August 2024 Updates

Here are ten useful regular expressions using capture groups for different tasks with ABC notation.

1. Extract the Title of the Music:

^T:s*(.*)$

2. Extract the Key Signature:

^K:s*(.*)$

3. Extract the Meter (Time Signature):

^M:s*(.*)$

4. Extract the Tempo:

^Q:s*(.*)$

5. Extract the Composer:

^C:s*(.*)$

6. Extract All Comments:

^(?!%%)%(.*)

For all of them, you can use $1 in the Replace string to use the extracted value.

Here’s a way to create a web page of the ABC for all the tunes in a tunebook using a regular expression.

Search:

(?:(X:.*n(T:s*)(.*n).*(?:n(?!n).*)*)nn)

Replace:

<h1 style=“font-family:monospace;font-size:18pt”>$3</h1>
<pre style=“font-family:monospace;font-size:12pt”>
$0</pre>
<hr>

Copy out the result and stick it inside of this basic web page wrapper:

<!DOCTYPE html>
<html lang=“en-US” prefix=“og: http://ogp.me/ns#”>
<body>

(Result goes here…)

</body>
</html>

On iPad, you now have an option to use the tool configured with a side-by-side view of the ABC and the notation similar to how it works on a desktop browser.

Open the “Advanced Settings” dialog (available from the “hamburger” menu at the top right of the top toolbar), and check:

With this feature enabled, I find it most effective to use the iPad in landscape orientation. 

Additionally, because the built-in onscreen keyboard on the iPad is quite large, particularly in landscape orientation, it would be ideal to use the tool with a Bluetooth keyboard or keyboard case when running in this mode.

At this time this feature is for iPad only and works on all three versions of the tool (Standard, Quick Editor, Offline-enabled).

Re: ABC Transcription Tools - August 2024 Updates

Pushed a minor but important update this morning that fixes (or at least improves) a long-standing bug in abcjs.

The abcjs issue is that if you started playing a tune, then clicked the pause button first to pause the playback, and then again to resume the playback the audio and the playback vertical bar cursor/note highlight would often be out of sync.

The only way to get them back in sync when this happened was to either rewind the playback or click in the progress bar to seek to a specific offset in the tune.

This bug has been in abcjs for as long as I’ve been using it, I verified that versions of my tool from over a year ago exhibited the same behavior.

Addressing this became particularly important when I added the play/pause button in fullscreen mode for the Quick Editor. It was just too easy to create the conditions for the bug to occur so I really wanted to fix or at least improve the behavior of abcjs around pause/resume.

My abcjs patch may not be a 100% fix, but it’s behaving much better than before in my testing and I haven’t run into the issue since pushing the patch.

You’ll want to make sure to get the latest code by doing a hard reload of the tool’s page.

You can tell you have the latest code if you go into the Advanced Settings and the version string (shown on the lower left corner) is:

Standard Editor and Quick Editor:
1522_260824_1100

Any version that starts with 1522 or greater has the patch.

Offline-enabled version:
0117_082624_1115

Any version that starts with 0117 or greater has the patch.

For the Offline-enabled version, if you can’t seem to get the latest version automatically updated after refreshing the page a couple of times, you can go into the Advanced Settings/Reset Settings and then check the “Force tool update after restart” checkbox, and follow the instructions for making sure the latest version is installed on your browser.

I’ve contributed the change back to Paul Rosen for integration into the official abcjs release channel at some future date.

Re: ABC Transcription Tools - August 2024 Updates

For the extreme power users, I’ve added a back door into the abcjs renderer parameters that can be set individually for each tune.

The abcjs renderer has many additional optional parameters that can be specified at tune render time.

Full details on the available options are here:

https://paulrosen.github.io/abcjs/visual/render-abc-options.html

To add custom abcjs rendering parameters to a tune, you can add the following annotation anywhere in the tune:

%abcjs_render_params (JSON parameter string)

Where the parameter string is an Javascript object in stringified JSON format.

Example #1: Render all the notation in green:

%abcjs_render_params {“foregroundColor”:“green”}

Example #2: Enabling Jazz Chord formatting:

%abcjs_render_params {“jazzchords”:true}

Example #3: Forcing 8 bars per staff (requires staffwidth parameter):

%abcjs_render_params {“staffwidth”:1000,“wrap”:{“minSpacing”:1.8, “maxSpacing”:2.7, “preferredMeasuresPerLine”:8}}

Note: This feature allows very low level control of the abcjs renderer. Improper parameters may cause unpredictable results or crash the tool.

Additional, use of some low-level abcjs rendering parameters such as “staffwidth” and “wrap” may cause issues with “Highlighting” mode in the tool.

https://tinyurl.com/4v8ydv9p

V:1
%%voicecolor green

Transposing instrument playback without visual transpose could be done transposing the music up a full step using the Transpose Up button and then using

%voice_tuning_cents -200

to shift the playback pitch down one full step. There are cases, particularly with backup chords (which seem to have some octave shift issues with visual transpose) where %voice_tuning_cents may be the preferred method.

If you want to create your own custom 4, 5, or 6 string stringed instrument tablatures, while constructing the JSON string, I suggest disabling the %abcjs_render_params command by changing it to:

%xabcjs_render_params

while you are editing your tablature JSON description and then enable it when you are done by taking out the initial x.

All tablature solutions require that the strings be in increasing pitch from low to high.

If you accidentally have the strings such that a lower pitch string is in the list after a higher pitched string, and there are ABC notes to be rendered, abcjs may just hang.

Here are a few starter parameter patterns.

Example #1: Generating custom Open-G (G-D-G-B) Mandolin tablature:

%abcjs_render_params {“tablature”: [{“instrument”: “violin”,“label”: “Open G - GDGB”,“tuning”: [“G,”, “D”, “G”, “B”],“highestNote”: “f’”,“capo”: 0}]}

Example #2: Generating custom Open-G (D-G-D-G-B-D) Guitar tablature:

%abcjs_render_params {“tablature”: [{“instrument”: “guitar”,“label”: “Open G - DGDGBD”,“tuning”: [“D,”, “G,”, “D”, “G”, “B”, “d”],“highestNote”: “f’”,“capo”: 0}]}

Example #3: Generating custom Open-G (D-G-D-G-B) 5-string Cittern tablature:

%abcjs_render_params {“tablature”: [{“instrument”: “fivestring”,“label”: “Open G - DGDGB”,“tuning”: [“D,”, “G,”, “D”, “G”, “B”],“highestNote”: “f’”,“capo”: 0}]}
