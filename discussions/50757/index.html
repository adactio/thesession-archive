ABC Transcription Tools - January 2026 Updates

Happy New Year 2026!

Since retiring from a 45-year software development career in 2023, I’ve been developing the ABC Transcription Tools as an unpaid, open-source passion project that I freely share with the music community.

The tools are guided by a clear long-term vision and by how I personally use them — primarily creating interactive tunebooks and websites on desktop browsers and using them on both desktop and mobile.

I very much welcome specific feature ideas and concrete feature improvement suggestions.

Many great additions have come directly from users.

For example, Alix recently suggested adding optional extra measures at the end of Tune Trainer phrases to allow more time between repeats, which was a great idea and is now part of the tool.

What’s less helpful are comments about release cadence, overall project direction, or assumptions about my priorities or experience.

Decisions about where I focus my energy are made deliberately, informed by real usage analytics data and an ongoing continuous integration/continuous delivery (CICD) approach (sometimes with multiple updates in a day).

Feature requests are always welcome.

Comments about how the project should be run, or expectations of entitlement, are not.

The entire source code is available on GitHub. The link to the repository is in the User Guide.

Anyone who has an idea, a concern, or a different approach is welcome to download the code, make changes, and offer improvements back to the project.

Thanks to everyone who contributes ideas, testing, code, and encouragement—it’s genuinely appreciated and helps make the tools better for everyone.

Re: ABC Transcription Tools - January 2026 Updates

Hi GD,

Yes, website export would work fine or just generate a PDF tunebook with play links.

The tool is able to run offline, even opening share links offline because it is written as a Progressive Web App (PWA).

In a PWA, on first run while online, the tool installs what’s called a JavaScript “service worker” in the browser for the tool that acts essentially as a domain-specific proxy.

On first run of the service worker the service worker copies all the required resource for the tool (HTML, JS, CSS) to a persistent cache created in the browser for the domain (michaeleskin.com). This cache, like local storage or IndexedDB databases is retained essentially forever, or until the user deletes all data for the domain.

Once a service worker is installed, any future accesses by the browser first go to the service worker to any resource in the domain go first to the service worker, which looks in the domain-specific persistent cache and if it present, returns the resource. If it is not found in the cache, only then does it go to the Internet to read the resource remotely.

Everything required to run the tool is stored in the service worker cache, so the tool runs online or offline.

This is not the same “browser cache” that one generally thinks of for browsers, this is a feature of browsers that allow web applications to create persistent caches for this sort of purpose. “Clearing the cache” in your browser doesn’t touch it. Only deleting all browser data for michaeleskin.com will.

Offline use requires that the tool be run online at least once to setup the service worker and the service worker cache (this all happens completely invisible to the user).

I did this specifically so that my interactive PDF files can be used at music workshops where there is little or no internet service. Clicking on a title play link in the PDF goes to the browser, the browser sees that there is a service worker installed for michaeleskin.com, and then loads the and runs the entire tool from the service worker cache, never going to the internet.

This file is the service worker used by the tool and shows what resources are stored in the cache:

https://michaeleskin.com/abctools/service_worker.js

When the tool detects that an update is available while online (there is a version number in the code and a dedicated version number in a separate file not in the service worker cache so always read remotely), I clear the previous service worker cache and then repopulate it with the latest code.

There are other web-based tools that are also built as a PWA and run offline, one example is

https://folkfriend.app

I’m happy to answer any other technical questions you might have about the tool.

Re: ABC Transcription Tools - January 2026 Updates

Everything is client-side local to your browser. Nothing is stored on my site.

The only thing read from my site after first run are the individual instrument notes used for the tunes as they are needed, and even those are stored in an IndexedDB database in the browser and are available for use offline.

Please refer to this section in the User Guide for more information on offline use of the instruments:

https://michaeleskin.com/abctools/userguide.html#app

The need for generating the SVG tune images depends on the style of website.

To meet fundamentally different website needs and use cases, there are four different styles of websites available as described here (with examples of each):

https://michaeleskin.com/abctools/userguide.html#generate_website

The Basic style is just a list of tune names with hyperlinks that contain the share links. Clicking on a tune name opens the tune in the tool in a new browser tab.

The Tune Image Gallery and Tune Image Lightbox styles embed links to the SVG images of the tunes on the webpage and then attach play links to those images. Clicking on the static images on the page opens the tune in a new tab.

The SVG images are required for these two image-based styles of websites to work, and yes, deleting them will break the website.

“Full-Featured” style websites launch the full tool in an iFrame embedded on the web page and have the ability to change instruments and tablature styles. They are fully self-contained with all the play links in a Javascript data structure that is used to set the URL of the iFrame when the tunes are selected from the dropdown.

Essentially all my demo tunebook websites at:

https://michaeleskin.com/tunebooks.html#websites_irish

are of this Full-Featured style.

Sounds like you’d probably best be served by the Full-Featured option. One file, no external images, completely self-contained.

I encourage you to look at the actual HTML/CSS/Javascript in the .html file generated by each of these website style options and I think how they work will become more clear.

My goal was to make it easy to export multiple styles of websites for different needs without any technical knowledge while still providing easy customization for someone comfortable with HTML/CSS/Javascript.

Additionally, the share links generated by the tool and used for both exported interactive PDF files and websites contain the entire ABC compressed in LZW or Deflate format. Everything it takes to reconstruct the tune(s) is in the share link. The link opens in the tool, the tool sees that there is a lzw or def URL parameter, it extracts it, decompresses the data in the parameter and that decompressed data gets loaded into the editor. If it’s a play link (&play=1), the Player is then automatically opened.

Re: ABC Transcription Tools - January 2026 Updates

Recently, a friend contacted me about issues he was having with characters with diacritical marks not rendering properly in the tool for a set of French-Canadian tunes.

Turns out his files were originally created in “ABC Explorer”, an older legacy Windows program and were encoded in Windows 1252 Western European text encoding and letters with diacritical marks were all messed up in the rendered ABC in my tool.

Generally tools on the web, including mine, prefer text in UTF-8 encoding.

You can easily convert these older legacy files from Windows 1252 to UTF-8 in many text editors, or even simpler, use a free online text encoding tool like this one:

https://localizely.com/text-encoding-converter/

If you don’t have characters with diacritical marks on them in your ABC, even if from an older Windows tool, you may never see this problem and don’t have to anything, it’s isolated to how these characters are encoded in Windows 1252 vs. UTF-8.

I’ve added a section in the next update of the User Guide addressing explaining this issue and including a link to the online encoding conversion tool.
