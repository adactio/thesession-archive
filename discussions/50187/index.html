ABC Transcription Tools - May 2025 Updates

New demo video of the latest version of “Create Tune Set” which is by default setup for playing sets, but can also be used just as easily for creating tune sets and adding them to your ABC.

Tune sets can be created and opened for playback or editing in a new browser tab or appended to the end of the current ABC.

Click the tunes in the tune list to add them to the set.

Numbers appear at the right of the tune names showing the tune order in the set.

Click a tune again to remove it from the set.

By default, the tune set is opened in the Player in a new browser tab.

When opening tune sets in a new browser tab, if you want the set to open in the ABC editor instead of the Player, check the box labeled “New browser tab tune sets open in the editor”

If you want to instead append the tune set to the current ABC, uncheck the box labeled “Open tune set in a new browser tab”

You have the option to have the tunes in the set repeat when played and to set the number of repeats.

Settings are saved and restored the next time you run the tool.

The video is of the “Create Tune Set” features available in version:

2461_050125_1500

or later.

The version number is displayed at the bottom left of the “Settings” dialog in the standard editor.

If your version starts with a number less than 2461, click the version number to do a manual update of the tool.

I’ve pushed an update that improves how the tool deals with sorting when there are diacriticals.

To take advantage of this you must have the actual character with the diacritical in the ABC, for example:

SEÁN

and not the escaped representation that uses a slash followed by a single quote (can’t type it here, the site collapses the example).

To make escaped diacriticals simple to deal with, I’ve added a new

“Normalize Diacriticals”

command on the “Hamburger” menu that will replace all escaped diacriticals in the entire ABC with the actual characters. After doing the operation, you’ll probably want to re-save the ABC file.

The new version improves the sorting results when using the “Sort Tunes by Tag” and sorting by the tune titles as well as when adding a sorted Table of Contents or Index to your exported PDF files.

The new sorting order effectively ignores the diacriticals when sorting giving a much more natural looking sort order result.

The new sorting with improvements for diacritical sorting is in version:

2465_050325_1000

or later.

A user was having an issue where they wanted the last tune in a tune set of three tunes pushed to it’s own page in the PDF.

Remember that tune sets are essentially one giant tune, so making this happen cleanly was a bit of a puzzle.

The best and most reliable way I’ve found of doing this is to put some additional vertical space before the next-to-last tune using

%%vskip 70

or whatever is required, pushing it down the first page, and then the final tune naturally flows to it’s own page.

%%newpage

in my tool is only for forcing individual tunes to a new page when generating PDF files with multiple-tunes per page. It doesn’t work in the middle of a tune.

Example, the set in the share link below when exported to PDF in portrait orientation, letter-sized page, one tune-per-page (doesn’t matter, since it’s a tune set, it’s only one tune anyway) has the final tune on it’s own page.

Without the

%%vskip 70

before Kathleen’s the title of the last tune would have been on page 1 and the rest of the tune on page 2.

Trying to use the %%vskip to move the last tune down causes that extra space to be included in the last tune’s space and displaces it down the second page so while it seems like the obvious solution, and is what I tried first, but it’s not the best one.

The optimal solution is to shift the next-to-last tune down the page a bit using %%vskip and allow the last tune to flow naturally to the next page.

Re: ABC Transcription Tools - May 2025 Updates

I’ve pushed out version 2475_050525_1530 that fixes a few long-standing issues in my custom version of abcjs:

1) The “, The” article reverser wasn’t being run in abcjs for subtitles, only for titles.

By default the notation renderer will reverse “, The” and “, An” style articles to the front of tune titles or subtitles.

This was showing up in the notation on tune sets when the subsequent tune titles were of the form “Kesh, The” and similar constructs.

To disable this behavior, you can add the following private annotation to any tune:

%no_title_reverser

The presence of this annotation in a tune will force both the displayed notation in the editor, exported PDF notation, and tunes played from play links to have the title article reverser disabled.

If placed in the ABC file header, it will apply to all of the tunes.

2) %%titlecaps wasn’t working for subtitles.

3) %%titlecaps wasn’t working if in the ABC file header.

These fixes are in version:

2475_050525_1530

or later.

The version number is displayed at the bottom left of the “Settings” dialog in the standard editor.

If your version starts with a number less than 2475, click the version number to do a manual update of the tool.

WhistlingFionn, really, for what you’re doing, the PDF exporter, either the one built-in to the tool or just doing a browser-native PDF export would do the job.

Both are searchable by tune name, even if there isn’t a Table of Contents or Index because I specifically inject additional information into the PDF to make it possible to search even if there aren’t play links associated with the tunes.

You could also just export a notation incipits or ABC incipits PDF, which would be tiny, searchable, and clicking the tunes would open them in the browser.

If you still absolute need a website version:

The Image Gallery and Image Lightbox websites export a .html file and also all the SVG files that are used for the images. These images are not in the html itself, but are referred do in the generated code.

You need to have all of SVG files in the same directory as the .html file to use the website, either hosted or on your own computer.

More details here:

https://michaeleskin.com/abctools/userguide.html#generate_website

with a demo video of all four available website styles here:

https://www.youtube.com/watch?v=976COaNUt6g

Only the basic style website style would support searching, since it is essentially a linear stream of tune names and links.

The tune image lightbox and full-featured websites both have popups that list all the tunes.

Please take a look at the documentation and all the possible options for both PDF export (both the custom PDF exporter in the tool as well as just using the one in your browser) and website export, and figure out one that best meets your needs.

If none meet your needs, perhaps some other tool would better meet your requirements, but I strongly suggest seeing if you can use what’s already available because I have no plans to add any additional website export styles at this time.

If you are working with a large ABC tunebook and want to create multiple sets of tunes, not concatenated (just individual tunes), but in a specific order:

1) Load the large tunebook ABC into the Quick Editor

2) Click “Delete Tunes” on the ☰ menu

3) Click “Select All”

4) Unselect the tunes I plan to make into sets

5) Click “Delete” to remove the unused tunes

6) Click “Reorder Tunes” on the ☰ menu

7) Drag the tunes into the set order you want

8 ) Click “OK”

The process would be the same in the standard version of the editor, but if the tunebook is >200 tunes, I’d suggest using the Quick Editor so you don’t have to wait for notation rendering just to delete and re-order tunes.

Someone on another forum was using “Create Tune Set” to do this and then was trying to break the concatenated sets apart with X: tags, which was about the most convoluted way I can imagine one might just put some tunes in a specific order from a tunebook.

Re: ABC Transcription Tools - May 2025 Updates

I’ve pushed out a new version that has a new PDF annotation that will allow you to manually set the first page number.

This can be useful, for example if you have a mix of players using printed PDF tunebooks and tablets running a PDF reader.

By default the tune page numbers start at 1, but PDF readers consider the title page page 1, so that’s where the confusion can occur in these mixed real/virtual PDF groups.

If you want to set the first page number for the first tune in the PDF to a specific value, you can include the following annotation at the top of the ABC before exporting the PDF:

%firstpagenumber 3

or whatever you need the value to be.

The offset page numbers will both be reflected on the pages as well as the Table of Contents and/or Index files.

Again, this is a manual override value. The tool cannot do this for you.

You may need to first export your PDF tunebook without the annotation, see how many pages the Title Page and Table of Contents take up, then add the %firstpagenumber annotation matching that number of pages, and then re-export the PDF file.

This feature is in version

2487_050825_0900

or later.

Re: ABC Transcription Tools - May 2025 Updates

May 24, 2025 weekly update wrap-up:

I’ve added a new feature to the tool that injects an %abcjs_rendering_params annotation into the ABC tune(s) as required to generate custom stringed instrument tablature for 4, 5, or 6-string stringed instruments.

Strings are numbered from low to high and use ABC pitch names.

Each string must have a different pitch and be higher than the previous one.

This means that “re-entrant” tunings like for Ukulele and 5-string Banjo are not possible.

This feature should work well for essentially any custom Mandolin, 5-string Cittern, or 6-string Guitar tuning.

Custom tablature settings override any tab setting on the toolbar buttons below the editor in the tool.

If the feature has been used previously on a tune, the existing %abcjs_render_params annotation and related comments will be replaced with a new one.

If you copy and paste a custom tab annotation to the ABC file header section before all the tunes, and force a redraw of the tunes (easiest way is to click Snapshot and then Restore or save and re-open the ABC file), it will get applied to all of the tunes.

Values are saved and restored the next time the tool is run.

Strong warning about hand editing the injected custom stringed instrument tablature %abcjs_render_params annotation

The custom stringed tablature annotation works at a very low level in the abcjs rendering system.

A malformed custom tablature annotation can easily crash the tool.

If you want to manually edit the injected custom tablature annotations, particularly the mapping of strings to notes, it will always be better to use the Custom Stringed Instrument Tab feature to inject a replacement custom tablature annotation since it checks the values and will only allow a valid annotation to be injected into the ABC and will automatically replace any existing annotations.

There is now a nice workflow improvement to the Save behavior.

As in all previous versions, if you click the “Save” button, it will always bring up the dialog where you can enter a file name.

If the file had been saved before, the previously entered file name will already be filled into the box.

In this new version, if you use the keyboard equivalent for “Save”:

⌘+S on Mac or Ctrl+S on Windows/Linux

and the file has not already been saved, it will bring up the file save dialog exactly as if you had clicked the “Save” button.

If the ABC was loaded from a file or previously saved, it will just save the file with the same filename as it was saved with originally without bringing up the file name entry dialog.

Browsers never save over an existing file, they will save a new version of the file with the same name and an incrementing number postfix, so you don’t have to worry about damaging a previously saved file, each new save will be in its own file.

When using the keyboard shortcut, the “Save” button will briefly change to say “Saved!” to give some feedback that the save operation occurred.

If you want to save the ABC file under a different file name, just click the “Save” button instead of using the keyboard shortcut.

Please let me know if you run into any issues with this new workflow improvement.

Another power user tip:

On desktop browsers, you can Alt-click any tune in the ABC to select it in its entirety.

I’ve fixed a long-standing abcjs issue related to showing bar numbers with

%%barnumbers 1

and multi-measure rests, which can be specified in ABC using for example:

Z4

for a four measure rest or

Z2

I’ve released a new version of the tool that adds dynamic loading of two additional Google Noto-Serif and Noto-Sans fonts to support Chinese characters on the PDF Title page, Table of Contents, Index, Headers and Footers.

While Chinese characters were always supported in the notation, the Javascript PDF creation library I use had a limited set of built-in fonts (Times, Helvetica, and Courier).

Now when either of the Noto fonts are selected in the PDF export dialog, they are loaded on-the-fly (they are quite large, so I didn’t want to load them if they aren’t being used) and made available to the PDF engine.

The fonts used are Google Noto Sans Traditional Chinese and Noto Serif Traditional Chinese. They support both Chinese and Western characters including diacriticals and are both quite pretty even if you aren’t using Chinese characters.

Additionally, you can now set the PDF header and footer font size using a new annotation:

%headerfooterfontsize 12

or whatever value you want.

You can now set the font size for the title page title and subtitle using the following annotations:

%titlefontsize font_size - Title page title font size. Default is: 24.

%subtitlefontsize font_size - Title page subtitle font size. Default is: 16.
