Re: ABC Transcription Tools - December 2024 Updates

I’ve added a new custom %abcjs_render_params option that lets you override the default vertical space padding between the notation and the tablature (if being used).

For example, to reduce the space (units are half the height between the lines on the staff, default is 3), try different values until you get the result you want) put this anywhere in your tune’s ABC:

%abcjs_render_params {“tabPadding”:0}

This can be useful especially for those cases where you have text under the notation as well as tablature.

For most tablature use cases, you shouldn’t need to change this value, but I found that when I wanted both the note names (added using the “Inject Shape Note/Solfège” feature in the screen shots below) below the staff <and> tablature, there was more space between the note names and tablature than I’d like.

This needs to be set in each tune for which you want a tabPadding override.

This feature is available in version 2159_120324_1300 or later.

Full details on %abcjs_render_params overrides can be found at:

https://michaeleskin.com/abctools/userguide.html#customabcjsparams

Re: ABC Transcription Tools - December 2024 Updates

This one is specifically for the Comhaltas folks creating tunebooks and using their Comhaltas ABC system.

This system uses D‘ E’ F’ instead of d e f for octave notes, first octave C is shown in the note name tab as

C,

instead of the standard ABC:

C

second octave C is:

C

instead of the standard ABC:

c

I’ve added a feature to the share link system where if you’ve enabled Comhaltas ABC for note name tab using the checkbox in the Settings, any share links created for either sharing on social media, PDF export, or website generation, will contain an additional URL param:

&cce=1

that when seen by the tool on opening a share URL make sure that if the user selects the note name tablature or is the default for the exported PDF tunebook or website, it will show the Comhaltas ABC format.

Previously, it would show either standard or Comhaltas ABC based on the user’s Settings.

The new system allows Comhaltas folks to override the user’s note name tab settings for the tunebooks they specifically want to have the note name tab shown in the Comhaltas ABC format. The override doesn’t change the user’s settings permanently, just for the display of the tune with the &cce=1 parameter in its share link.

Re: ABC Transcription Tools - December 2024 Updates

As some of you probably know, abcjs doesn’t (yet) natively support P: tag part playback sequencing.

For those who have quite vociferously expressed their desire for support for P: tag based parts sequencing in my tool, rather than wait for it to possibly get implemented in some future version of abcjs, I’ve added an experimental opt-in “part flattening” feature to my tool’s Player.

It literally finds the parts in the ABC, then assembles them in the order specified in the P: tag sequence control string, then injects the reassembled ABC into the Player.

It’s not absolutely ideal, but it gets the job done as far as playback in this specified order and I kind of like seeing all of the parts in the playback order in the player.

It can handle common P: tag sequencing strings like:

P:AABBCC

P:AABBAACCAADD

and even part repeat numbers:

P:A2B2A2C2A2D2

as well as parts grouping with parentheses:

P:(AB)2C(AB)2D

A few caveats:

First, it’s something you have to opt-in for on a per-tune basis with a new tool-private annotation:

%play_flatten_parts

Second, the parts names must be single capital letters from A to Z:

Do this:

P:A
P:B
P:C

not

P:Verse
P:Chorus

Since it’s an opt-in feature and only turned on on a per-tune basis with the %play_flatten_parts annotation, it should never affect normal operation of the tool.

Hopefully, this will address the basic requirement of defining parts and their playback order, particularly for .MP3 and .WAV export without requiring you to have to manually copy and paste parts.

Here are the full details in the User Guide:

https://michaeleskin.com/abctools/userguide.html#flattening_parts

I’ve pretty massively enhanced the functionality of the “Quick Editor” to be able to handle tunebooks with hundreds or even thousands of tunes.

Originally, the “Quick Editor” was primarily for editing and quickly playing single tunes.

Now you can now simply click on different tunes in the ABC editor and the tool will render the tune notation for that tune as well as load it for immediately playback.

This allows you to easily work with very large tunebooks as it will only draw the tune that you are currently working with.

There are limitations in the “Quick Editor” as before:

1) No dedicated playback dialog or “Tune Trainer”
2) No ability to play selected portions of tunes
3) No PDF or Website Export
4) Highlighting mode only available for the first tune in the ABC.

The “Quick Editor” is available from the “Hamburger Menu” at the far right of the top toolbar in the standard version of the tool.

The enhancements are available in version 2195_122324_1900 of the tool. Please update to the latest version to get the new features.

Re: ABC Transcription Tools - December 2024 Updates

I’ve made the hidden title text injection for searchability optional now (on by default) for anyone who might want to use other tools like Adobe Acrobat’s OCR feature to inject their own searchable text features.

For example, if you have a PDF with a lot of background information text added using %%text or N: tags, it’s possible to use the Adobe Acrobat OCR feature to detect and index that text to allow you to search in your text in the PDF.

Using Adobe Acrobat OCR can also be handy for making it possible to find all the tunes that have a specific displayed tune style indication.

In this case, if the hidden title text injection had been done by my PDF exporter, then along with the hidden title text, the Adobe Acrobat OCR operation would also detect the title text for the tunes in the tune image and you’d have two matches for each tune. Turning the title text injection off keeps that from happening.

Most users should leave the title injection on, but the option is there to disable it.
