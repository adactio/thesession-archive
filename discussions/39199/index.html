Re: Quality sheet music from ABC Notation

EasyABC is currently an open-source project. There is a possibility that some specific ornaments could be added in if you address the right individuals. The ability of EasyABC to provide those specific ornamentation relies on yet another open-source developers efforts on the software that renders the abc notation. I believe that’s abc2ps or something like that. You can find the forums for those projects and make a plea and you may or may not have some success at some point in the future.

Alternatively, you could purchase something like Sibelious but I’m unaware if that program can import abc notation. Certainly, after putting together a tunebook for a group that exceeded 200 pages one of the members of that group completely dissed the abc notation used to put it together because it wasn’t “professional” software like her Sibellious.

To date, out of the 652 pages of hand-written tunes I’ve been converting to abc notation, I’ve only found a half-dozen or so ornaments that are unsupported in abc notation. Those I’ll just explain away in the preface as there is nothing that can be done for them currently. I do love EasyABC though and it’s pdf output is actually very good on my iMac so I would say the output quality is very, very good - minus the missing ornamentations I’d like to have. Note that the abc2midi output of any of these programs is really an awful mechanical rendering and I suppose you could say that that output is less than, uh, magnificent. You sort of have to be specific or careful at what you call not great quality as literally everything “under the hood” is done by different software packages that are supported by people working on them in their spare time for no pay. There is a limit to what you can expect for free.

The <Larsen> font can be used in EasyAbc, if it on the same computer and it’s use is designated in the abc file. The ‘simplest’ way to do this is the same way guitar chords are used, above a note.

X:1
T:Grey’s Way
K:G
%%gchordfont Larsen
…

This example is most basic use, though it does work in EasyAbc. If you read Guido’s Abc manual he has some great information about placing ornamentation and annotation in the score.

Earlier I recommended the simplest way to use Larsen font ornaments would be the same as guitar chords, between double quotes “ ”

That’s the most simple method. If you have Guido’s Abc manual he has a section (beginning on p. 32)
2.2.7 Text Annotations: “ˆ _<>@” {above, below, right, left, coordinates from notehead}
Each of these annotation placements are between double quotation marks (same as gchords) but they need a special character before the annotation.

So if you get how gchords work, you can get the same result using the special character ^ to place a text annotation above the note. You just need to give the postscript command for an annotation font.

It’s also possible to position Larsen font ornaments above the notehead anywhere you need them by using the special character @ and specifying x,y coordinates from the notehead.

All of this is considered text annotation, written between double quotation marks. The only difference is without the special characters you can use the postscript directive
%%gchordfont ______
with the specials characters it is
%%annotationfont ______

Here is an example using the above “^” annotation and then the “@” form.
It should work in EasyAbc if you have the Larsen font.

X:1
T:Slide Notation
L:1/4
K:G
%%annotationfont Larsen 12
(E“^S”F)|(E“^s”F)|(E“@1,23S”F)|(E“@1,23s”F)|

^ above the staff;
_ below the staff;
< to the left of the note;
> to the right of the note;
@ must be followed by two numbers X and Y, separated by a comma and optionally
followed by a space. The annotation will be printed from the centre of the note head (the
lowest note, if in a chord), with an offset of X horizontal and Y vertical points.

package colman.conversion_utilities;

import java.io.File;
import java.io.IOException;

public class AbcToPostScript extends NotationFormatConverter
{
// Purpose: Convert an abc transcription to a sheet music score in SVG format
// 1. An entry needs to be added to the Path environment variable for abcm2ps
// 2. The outputFilePath folder must first exist before this can run

private String externalProgram; //Will be abcm2ps in this case
private String inputFilePath;
private String inputFileName;
private String outputFilePath;
private String fileNamingStyle;

public void convertFormat() //Abstract method inherited from NotationFormatConverter
//Launch external program abcm2ps to convert an abc transcription to PostScript format
{
try
{
ProcessBuilder abcToPs = new ProcessBuilder();
abcToPs.directory(new File(outputFilePath));
abcToPs.command(externalProgram, inputFilePath + inputFileName, fileNamingStyle);
abcToPs.start();
}
catch (IOException e)
{
System.out.println(e.getMessage());
}
}

//Setter methods for private fields omitted for brevity
}

This very crude and ugly class then converts the PostScript to PDF:
--------------------------------------------------------------------------------
package colman.conversion_utilities;

import java.io.IOException;
import java.lang.ProcessBuilder;

public class PostScriptToPdf extends NotationFormatConverter
{
// Purpose: Convert a PostScript representation of a score to a PDF document containing the visual score
// Note: The outputFilePath folder must first exist before this can run

private String externalProgram; // Will be GhostScript in this case
private String pathToGhostScript; //GhostScript doesn’t seem to run correctly without providing an absolute path to the .exe
private String inputFilePath;
private String inputFileName;
private String outputFilePath;
private String outputFileName;

public void convertFormat()
//The implementation of this method works, but needs to be redesigned to make it more elegant
//Opens Windows CMD and launches external program GhostScript to convert a PostScript file to a PDF file
{
String pathAndExeForGS = pathToGhostScript + externalProgram;

try
{
ProcessBuilder psToPdf = new ProcessBuilder(“cmd.exe”, “/c”, pathAndExeForGS, “-sDEVICE=pdfwrite”, “-o”, outputFilePath + outputFileName, inputFilePath + inputFileName);
psToPdf.start();
}
catch (IOException e)
{
e.printStackTrace();
}
}

//Setter methods for private fields omitted for brevity
}

The coordinates are points away from the notehead. If I have it right (from Guido’s manual) each point is approximately 0.353 mm.
