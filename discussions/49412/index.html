ABC Transcription Tools - July 2024 Feature Updates

On those rare instances where a tune crashes the abcjs renderer (as indicated by the spinner never going away), I’m now detecting the crash and putting up an alert that shows the offending tune name.

You can then isolate that one tune, remove it from the tunebook, whatever is required to fix it, and then the tunes will re-render.

If there is another issue, the same alert will show.

I used this to isolate 2 bad tunes in a collection of 1300 and it was so much easier than before.

Previously, I’d turn on the:

“Show tune rendering progress in Javascript console”

option in the Advanced Settings and watch the rendering progression in the console, and when it stopped, I knew which tune was bad.

Now it will tell you right in the tool.

What’s nice is that when it detects a crash the spinner goes away and you can continue working.

Previously, if the tool would crash as a result of a bad tune, you’d have to reload the page.

To expand on the range of playback options for offline use, for I’ve added a new experimental option in the Advanced Settings to the offline-enabled PWA version of the tool:

Info from the User Guide for the PWA version:

Allow previously cached instrument sounds and reverb to be used offline (experimental)
The tool caches all soundfont instruments and notes as they are played in a local database.
When this option is checked and the tool is offline, it will still allow playback of the specific soundfont instruments and notes previously cached in the notes database while online.
It also will allow any reverb to take effect if it has been used online previously.
Any soundfont instruments and notes not played previously, and not in the notes database will result in silence for those notes.
Similarly, if the reverb setting (room, hall, chamber, church, etc.) is changed offline to one not previously used, then unpredictable results may occur.

If this option is not checked, the tool will default to a piano sound for all sounds and reverb will be disabled. A percussion sound is also available for use with the metronome option in the player.


Explanation:

When you are using the tool and playing tunes, I store all the samples for the soundfonts, instruments, and notes you actually play in a local database.

When this option is checked, and you are offline, rather than default to a simple piano sound and no reverb, it will try to pull the notes from the database. If you’re playing tunes all the time using the same samples, there is a very good chance that all the notes are already in the database along with whatever reverb settings you commonly use.

https://michaeleskin.com/abctools_pwa/abctools.html

To understand how the offline-enabled version works, here’s an overview of how Progressive Web Apps (PWA) use a client-side browser component called a service worker to be able to run off-line.

The first time the offline-enabled version at:

https://michaeleskin.com/abctools_pwa/abctools.html

is run in your browser while online, it registers a server worker instance in the browser.

The service worker on first registration reads all the resources for the tool and stores it in a special cache in the browser specifically provided for service workers to manage.

After that, when the browser request resources, if there is a service worker installed for the tool, it first requests the resource from the service worker which can then pull it from its cache whether it’s online or off-line. This happens before the browser even tries to read the resource from its own cache.

If the resource isn’t in the service worker managed cache then it is fetched either from the browser cache or if not there, read from the Internet just like any other standard resource request.

I install all of the resources that are required to run the tool in the service worker cache when the service worker is registered the first time, and that is what makes it possible for it to run off-line.

If the tool is being run online and I want to push an update to the code, the browser detects I changed the version number of the service worker code, the previous cache is deleted, the new service worker is registered, the old one unregistered, and a new cache of the updated code is read from the internet and stored for offline use.

Service workers are essentially client-side proxy servers that have their own resource caching system and registration and updating process.

It’s a pretty amazing but also pretty complicated system that has taken me a long time to understand and get right.

The only resources read during use of the tool are the notes for the instruments used for playback.

When playing tunes while online, the fetched instrument samples and reverb settings are stored by me in a separate client-side IndexedDB database in the browser and not the service worker caching system.

The tool will pull its instrument notes from that database which gets populated with instrument notes when you play tunes while online.

The idea is you populate the notes database with the instrument and notes you use all the time when you play tunes while online, and those automagically become available offline.

The “Instrument Notes” sub-dialog on the “Manage Notes, Reverb, and Tune Search Databases” dialog is your friend here and makes it easy to get all the notes in the database for the instruments you commonly use, since the only notes in the database will be the ones in the tunes you actually open in the player.

Full details in the User Guide at:

https://michaeleskin.com/abctools_pwa/userguide.html#pwa

and

https://michaeleskin.com/abctools_pwa/userguide.html#manage_databases

For those who prefer to run the source code directly from the GitHub repo, it should be possible to run the off-line version’s abctools-offline.html from the abctools_pwa directory in the source code on the GitHub repo and get offline playback.

This is a technical post about an experimental idea that may allow you to use my interactive PDF tunebooks offline using Chrome as your default web browser on desktop systems.

I don’t have a solution to recommend for mobile devices.

I’m going to need to keep the standard and offline versions independent for a while.

Currently, all share links in PDF files point to the standard site, which means when you are offline, they almost certainly won’t work.

I’ve been investigating free Chrome extensions that can do dynamic redirects for you and I think I’ve found one on the Chrome Web Store that will do the job:

Inssman

https://chromewebstore.google.com/detail/inssman-open-source-modif/ghlpdbkhlenlfiglgphledhfhchjfjfk?hl=en

With documentation here:

https://www.inssman.com/docs/introduction

You’ll must load the offline version at least once in Chrome to get it stored in the browser by the service worker for offline use.

https://michaeleskin.com/abctools_pwa/abctools.html

I also suggest loading up a few tunes and getting the notes database populated using the process I’ve outlined in previous posts and videos.

In Inssman, you can setup a redirect rule that when Chrome loads the standard site, it will redirect to the offline-enabled version and keep the same URL parameters, allowing the share link to be processed.

With Inssman installed, and this redirect rule in place, with Chrome as my default browser, if I click on a tune play link in a PDF tunebook, it gets redirected by Chrome and opens in the offline version, where I can play the tune and work with the ABC just like the standard version.

Here’s the details for creating the redirect rule in Inssman:

Under “Create Rule”, click “Redirect Request”.

Give it a name. I used:

Redirect ABC Transcriptions Tools Standard Version to Offline Version

For the conditions, you want:

If Request Wildcard https://michaeleskin.com/abctools.html*

Redirect to https://michaeleskin.com/abctools_pwa/abctools.html$1

I’m not able to test this in actual offline conditions, but it does work simulating offline using the Chrome Dev Tools, so please give it a try and let me know if it works for you.

Demo video:

https://youtu.be/FofL34WuzZE

I’ve made some huge progress on the offline-enabled version in the past few days, fixed a lot “didn’t know I didn’t know” category of issues around having a reliable and predictable updating of the offline version and making sure those changes are applied consistently across all platforms and browsers.

It’s looking very solid for me across Firefox, Chrome, and Safari on my Mac, and on mobile Safari on my iPhone and iPad.

I would greatly appreciate it if you would try it out if you get a chance and report anything odd that you run into. The two other users testing it are telling me things are looking quite solid, but I don’t want to make the offline-enabled version the official release version until I’m absolute certain it is as robust and stable as the standard version.

For those who are interested in having standalone share URLs or PDF tunebooks where the tunes open directly in the Editor when you click the tune title, I figured out an easy solution that wasn’t disruptive to the stability of the existing PDF generation in the tool.

The new directive is:

%links_open_in_editor

which can be anywhere in your ABC file.

It also will work with any of the other PDF features like Title Pages, Table of Contents, Index, etc. that you add from the “Inject PDF Tunebook Features” dialog when exporting PDF.

You’ll just need to manually enter this directive anywhere in your ABC for it to kick in during PDF export.

Adding %links_open_in_editor will override any play links that might be specified in the PDF features injected at the top using “Inject PDF Tunebook Features”.

They can both be present, but %links_open_in_editor will take precedence over %add_all_playback_links.

Re: ABC Transcription Tools - July 2024 Updates

TLDR: Custom instruments now have consistent volume independent of the soundfont in use.

Chances are nobody will notice, but you should find that all my custom instruments (whistle, flute, mandolin, tenor banjo, etc.) should have consistent volume now no matter which soundfont you are using for other instruments in a tune.

Some of the soundfonts were created with different default volume gain values for the instrument notes.

In abcjs, there is a volume multiplier applied to the sounds based on which soundfont is in use for a tune to compensate for any difference between soundfonts and allow for consistent volume range across the soundfonts.

This same volume multiplier value would have been applied to any of my custom instruments used (which are the same samples no matter which soundfont is used), resulting in different volume levels for the instruments depending on the soundfont in use for other instruments in a tune.

For example, if you had a tune with a whistle for a melody and piano for the bass and chords, the whistle would be much louder if using the FatBoy soundfont instead of Fluid because the FatBoy default multiplier was 3.25 and the Fluid default multiplier was 2.0.

I’m now detecting when a custom instrument is being used for a note and applying a consistent volume multiplier for that instrument independent of the soundfont in use.
